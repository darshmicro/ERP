# Data Integrity Assessment (ALCOA+)

Assessment of the principal data flows against ALCOA+ and the technical control that supports each principle. Site SOPs (see `sop-requirements.md`) complete the controls.

| Principle | How the system supports it | Evidence / test |
|---|---|---|
| **Attributable** | Unique user ID per action (audit `user_name`, role, IP, session); e-signature with printed name, meaning and time; no shared accounts (unique usernames, SoD-09/10); system jobs run as the audited user `SYSTEM` | `test_crit_10`, audit tests, `scheduler` actor test |
| **Legible** | Structured records; controlled PDFs/XLSX with headers; no free-form overwrite of results | report tests |
| **Contemporaneous** | Timestamps are generated by the server in UTC; users cannot set transaction times; back-dated manual dates (e.g. bleed, immunisation) are validated against the future and logged | `test_bleed...`, ledger `txn_ts` |
| **Original** | First-captured results immutable; corrections via amendment keeping the original; approved versions never edited; GRN/checklist answers retained | QC amendment, versioned master tests |
| **Accurate** | Server-side validation, limits and rounding; calculations unit-tested against reference data; ledger/balance reconciliation; hash-verified documents | stats tests, `test_crit_13` |
| **Complete** | Mandatory fields, FK integrity, no orphan genealogy (issues must reference lot and batch), audit rows for every create/update/delete attempt, status history | `test_crit_14`, trace tests |
| **Consistent** | One source of truth per fact (ledger for stock; versioned masters for specs/BOMs); consistent UTC time; consistent numbering | numbering tests |
| **Enduring** | Retention policies (extend-only), legal hold, hashed archive packages, backup evidence and restore tests, DB triggers on append-only tables | retention + backup tests, restore qualification |
| **Available** | Search, trace, reports (37), exports with copy control, auditor role with read-only access | report/search tests |

## Data-flow assessment
| Data flow | Risk to integrity | Control | Residual |
|---|---|---|---|
| Vendor/material/spec masters | Unauthorised or silent change | Versioning, QA e-signature, SoD, audit, change control | Low |
| PO → GRN → lot → ledger | Wrong material accepted; quantity drift | Gate rules, checklist, second-person verification, atomic ledger | Low |
| Sampling → QC results → release | Result manipulation, self-review | Immutable results, analyst restriction, release chain, OOS workflow | Low |
| Issue → batch → reconciliation → output | Untraceable use; diversion | Mandatory linkage, reconciliation, deviation | Low |
| Release → dispatch → recall | Wrong product shipped | Dispatch gates, reservation, CoA link, recall derivation | Low |
| Audit trail / signatures | Tampering by DBA | Triggers, grants, HMAC chain — tampering is *detectable*; DBA access is a site control | Low–Medium (site) |
| Backup/restore | Silent corruption | CHECKSUM backups, restore test with chain verification | Low (site must execute) |
| Excel import | Bulk bad data | Staging, validation, approval, execute only unchanged rows | Low |
| Printouts/exports | Uncontrolled copies | Controlled-copy log + hash verification | Low |

## Open points for the site
1. Time source (NTP) and time-zone policy; 2. DBA/administrator access control and monitoring (the application cannot prevent a privileged operator from disabling triggers, but the audit hash chain will reveal the tampering); 3. Periodic audit-trail review procedure; 4. Backup execution and restore testing schedule; 5. Handling of paper/hybrid records (e.g., supplier CoA originals).
