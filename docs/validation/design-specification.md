# Design Specification (DS)

## 1. Architecture
Layered: **api** (FastAPI routers: validation, authentication, authorisation) → **services** (business rules, state machines, calculations; one transaction per user action) → **models** (SQLAlchemy 2 ORM) → database. Cross-cutting: **audit hooks** (`app/audit/hooks.py`) in the ORM flush path, **status engine** (`app/workflows/state_machine.py`), **approval engine**, **e-signature service**, **numbering**. See `docs/architecture/01-system-architecture.md`.

```
Browser (React) ──HTTPS──> Reverse proxy ──> FastAPI (uvicorn workers) ──> SQL Server
                                               ├─ document store (hash-verified files)
                                               └─ scheduler / scripts/run_jobs.py (daily jobs, SYSTEM actor)
```

## 2. Key design decisions (full list in `00-index-and-design-decisions.md`)
| Decision | Design |
|---|---|
| Stock authority (C-05) | `inventory_transaction` is append-only and authoritative; `inventory_balance` is a projection updated by guarded atomic `UPDATE` in the same transaction; reconciled by `verify_ledger` and a report |
| Versioned masters | STP/specification/sampling plan/BOM/vendor–material/SOP: draft-only edits, QA e-signature approval, supersede, point-in-time lookup; transactions pin the exact version |
| Holds as overlay | Quality hold is a record, not a lot disposition — releasing a hold restores the exact previous state; derived stock status |
| Products as materials | Single material master with SFG/FG types; BOM versions reference them |
| Status integrity | Status columns are writable only inside `transition_context()`; payload schemas never include them (BR-SEC-001) |
| Checks before writes | Authentication, SoD and gate checks run before the first write of a request (independent-session security events must not contend with open transactions) |
| Statistics (C-12) | σ within = MR̄/1.128 for Cp/Cpk, overall σ for Pp/Ppk, explicit status codes, Nelson rules, I-MR limits |
| Traceability | Mandatory FK chain (issue rows reference lot and batch NOT NULL); graph computed on demand |
| Time | All timestamps UTC from the server; `DATETIME2(6)` on SQL Server (hash-chain exactness) |

## 3. Database
127 tables, 20 append-only (INSTEAD OF triggers on SQL Server, BEFORE triggers on SQLite). Naming conventions give deterministic constraint names. Data dictionary and ER diagrams are **generated**: `docs/architecture/12-data-dictionary.md`, `13-er-diagram.md`. Migrations `database/migrations/versions/0001…0009` (autogenerated, reviewed, up/down/up verified on SQL Server; trigger lists frozen per migration).
Least-privilege model: `database/mssql/01_logins_and_grants.sql` (migrator / app / read-only accounts; DENY UPDATE/DELETE on append-only tables).

## 4. Security design
Argon2id password hashes; random 256-bit session tokens stored hashed; HttpOnly+SameSite cookies; per-session CSRF token; idle and absolute timeouts; lockout; login rate limit; RBAC with 298 permission codes, SoD rules (SOD-01…42) evaluated against a `record_action` log; security events (append-only); CSP and standard headers; production configuration fail-fast; upload validation (extension, magic bytes, size); spreadsheet formula-injection neutralisation; secrets only from environment/secret store.

## 5. Configuration
`system_configuration` keys with documented defaults (see `configuration-specification.md` §5), numbering registry (admin-editable with audit), workflow definitions (versioned, QA-approved), retention policies (extend-only), environment variables (`docs/manuals/configuration.md`).

## 6. Performance and capacity design
Stateless application processes (scale with workers); connection pool sized per worker (`MERP_DB_POOL_SIZE`, `MERP_DB_MAX_OVERFLOW`); keyset pagination for the audit trail; report previews capped; indexes on lot/material/status/foreign keys; verified under 50 concurrent users (`performance-and-load.md`).

## 7. Deployment
Docker images/compose (`docker/`), Windows service script (`scripts/run_windows.ps1`), Linux `run_dev.sh`; Caddy reverse proxy sample. `docs/manuals/installation.md`.
